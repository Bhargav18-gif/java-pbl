1. Abstract & Executive Summary

Modern outpatient healthcare departments manage hundreds of patient visits daily across medical specialties. Manual queuing and disjointed scheduling lead to significant patient waiting times, clerical appointment conflicts, and hazardous delays when handling emergency trauma arrivals.

The Hospital Appointment and Patient Queue Management System is a standalone clinical software application engineered in pure Java Swing by the Department of Data Engineering. The application features a medical design theme (Deep Navy, Pure White, and Sky Blue) and incorporates essential Advanced Java engineering paradigms:

  • Multi-Threaded Producer–Consumer Queue: Uses Java intrinsic monitors (synchronized, wait(), and notifyAll()) to guarantee thread safety between appointment dispatchers (producers) and consultation examination desks (consumers).
  • Strict Emergency Priority Triage: Maintains independent Emergency and Regular patient queues where critical patients receive non-preemptive priority over standard appointments.
  • Object-Oriented Architecture: Features an abstract base Person class with polymorphic subclasses (Patient and Doctor) and decoupled interfaces (Queueable, Searchable, QueueObserver).
  • Data Integrity & Exception Handling: Implements custom checked exceptions including DuplicateBookingException to prevent double-booking specialists for identical time slots.
  • Responsive GUI & Dynamic Observer: Offloads heavy tasks to background worker threads while routing UI mutations to the Swing Event Dispatch Thread (EDT) via SwingUtilities.invokeLater().

2. Introduction & System Objectives

Clinical facilities require strict coordination between reception triage, scheduled specialist appointments, and emergency admissions. Traditional desktop software frequently suffers from unresponsive user interfaces when processing concurrent tasks or fails to enforce strict priority during patient emergencies.

Core Engineering Objectives
  1. Construct an intuitive desktop interface with six functional modules: Dashboard, Patient Management, Doctor Directory, Appointment Dispatch, Priority Queues, and Consultation Desk.
  2. Implement thread-safe Producer–Consumer queuing utilizing Java monitor synchronization.
  3. Enforce strict priority queue dispatch ensuring emergency patients are attended before standard appointments.
  4. Eliminate scheduling conflicts through custom validation and duplicate-booking exception handling.
  5. Ensure 100% responsiveness on the Swing Event Dispatch Thread (EDT).

4.2 Multi-Threading & Producer–Consumer Pattern

The application features a bounded-buffer Producer–Consumer engine in HospitalQueueEngine.java. 

// PRODUCER METHOD: Adds patient tokens to queue with wait() and notifyAll()
public synchronized void produceToken(QueueToken token) throws InterruptedException {
    while ((emergencyQueue.size() + regularQueue.size()) >= capacity) {
        wait(); // Bounded buffer full: Wait for doctor to process tokens
    }
    if (token.isEmergency()) {
        emergencyQueue.addLast(token);
    } else {
        regularQueue.addLast(token);
    }
    notifyAll(); // Wake up consumers waiting for patients
    notifyObserversQueueUpdated();
}

// CONSUMER METHOD: Strict emergency priority queue retrieval
public synchronized QueueToken consumeToken() throws InterruptedException {
    while (emergencyQueue.isEmpty() && regularQueue.isEmpty()) {
        wait(); // No patients waiting: Consumer thread waits
    }
    // Strict Emergency Priority Enforcement:
    QueueToken token = !emergencyQueue.isEmpty() 
            ? emergencyQueue.removeFirst() 
            : regularQueue.removeFirst();
    notifyAll(); // Wake up any producers waiting for buffer space
    return token;
}

4.3 Java Collections Framework Utilization

  • LinkedHashMap<String, Patient / Doctor / Appointment>: Guarantees $O(1)$ constant time lookup by primary ID while preserving natural insertion ordering for directory tables.
  • LinkedList<QueueToken>: Implements double-ended queues for separate Emergency and Regular queues, providing $O(1)$ head removals and tail additions.
  • ArrayList<ConsultationRecord>: Dynamic array storing consultation history records and observer subscriber lists.
  • Comparable<QueueToken>: Custom comparator prioritizing emergency tokens ahead of regular tokens.

4.4 Custom Exception Handling

The system implements checked exceptions to protect against illegal state mutations:

  • DuplicateBookingException: Thrown when an appointment booking conflicts with an existing appointment for the same specialist at the same date and time slot.
  • InvalidInputException: Thrown when patient or clinical inputs fail business validation rules.
  • QueueEmptyException: Thrown when consultation processing is initiated with no patients waiting.
  • DoctorUnavailableException: Thrown if an operation references an inactive specialist.

5. Module Walkthrough & Clinical Workflows

5.1 Dashboard Screen

Provides real-time clinical visibility through 6 KPI summary cards (Total Patients, Total Bookings, Waiting in Queue, Emergency Queue, Completed Consultations, Active Doctors). It features an interactive Live Queue Status Banner that monitors active consultations and a Recent Appointments table with status badges.

5.2 Patient Management

Enables comprehensive patient registration with fields for Name, Age, Gender, Phone, Email, Blood Group, Residential Address, Allergies/Medical History, and Emergency Contact. Includes real-time multi-field text search filtering and a direct "Send Selected Patient to Live Queue" dispatch button.

5.3 Doctor Directory

Manages specialist profiles across Cardiology, Neurology, Pediatrics, Orthopedics, General Medicine, Dermatology, Oncology, and ENT. Tracks room numbers, qualifications, years of experience, available days, and consultation shift timings.

5.4 Appointment Scheduling & Conflict Resolution

Provides automated unique appointment ID generation (APT-XXXX), patient/specialist dropdown mapping, calendar date selection, and standard time slot booking. Validates every booking to eliminate duplicate doctor schedules and provides rescheduling and queue dispatch actions.

5.5 Dual-Priority Queue Management

Displays separate visual tables for the Emergency Priority Queue (Crimson accent) and the Regular Patient Queue (Navy accent). Features an automated "Next-in-Line" compute banner and a Walk-In Token Generator (Producer) allowing receptionists to triage walk-in cases instantly.

5.6 Consultation Desk (Doctor's Workstation)

The clinical examination workstation where doctors examine patients retrieved from the queue. It includes fields for clinical vitals (BP, Heart Rate, SpO2, Temperature), Symptoms, Diagnosis, Prescription, and Advice. Includes a toggleable multi-threaded background simulation engine and a comprehensive consultation history archive.
